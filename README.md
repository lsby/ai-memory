# AI Memory

`@lsby/ai-memory` 是一个专为 AI 智能体设计的**类脑长期记忆与自演进系统**。

基于嵌入式 **PGlite + pgvector**，它在本地 Node.js 进程内即可完整运行，无需搭建任何外部数据库。它打破了传统智能体“聊完即忘”与“死板外挂 RAG”的局限，为智能体构建了一套具备**分层认知、图谱联想、仿生遗忘与技能自演进**的完整心智系统。

---

## 为什么需要这样一套记忆系统？

传统的 LLM 智能体通常只有两种记忆手段：

1. **上下文滑动窗口**：聊着聊着前面的内容就被粗暴截断，跨会话直接失忆。
2. **传统外挂 RAG**：收到用户提问后，系统机械地根据向量相似度搜出几条文本，强行拼进 prompt。

这两种方式存在根本缺陷：

- **AI 是被动的**：外部系统喂什么它就看什么，无法像人类思考一样**自主联想、顺藤摸瓜**去深挖线索。
- **记忆只增不减**：缺乏淘汰机制，历史越多噪音越大，检索质量持续恶化。
- **缺乏抽象与进化**：经历过的事只能当文本死记，无法将反复出现的逻辑抽象沉淀为“通用规律”或“可执行新技能”。

`@lsby/ai-memory` 的目标就是模拟人类大脑的工作机制，让智能体真正拥有持久的思考深度、自我净化能力与成长性。

## 核心设计理念

### 1. 三级记忆模型（分层认知）

人类大脑不会把所有信息平铺在意识中。本系统将记忆划分为三个层级：

| 等级         | 角色定位                          | 存储与生命周期特征                                                                                             |
| :----------- | :-------------------------------- | :------------------------------------------------------------------------------------------------------------- |
| **零级记忆** | **核心法则 / 人设**               | 智能体的“自我定位”与底层铁律。**无条件常驻每次对话**，优先级最高，免受遗忘机制影响。                           |
| **一级记忆** | **工作记忆 (Working Memory)**     | 当前任务正在使用的即时上下文。常驻当前任务，容量严格受限；满载时自动将低分记忆降级流转至二级记忆。             |
| **二级记忆** | **潜意识网络 (Long-term Memory)** | 智能体长期沉淀的海量经验库。平时隐于后台，系统在对话时按需唤起相关片段及**发散线索**，受仿生遗忘曲线持续冲刷。 |

### 2. 仿生遗忘：基于“信息冲刷”，而非物理时间

没有遗忘的记忆系统最终必然死于信息过载。本库将记忆衰减改造为**基于信息量冲刷 (Information Displacement) 的衰减模型**：

- **摆脱物理时钟**：现实中人遗忘某件事，往往不是因为日历翻过了多少页，而是因为“大脑涌入了太多新事物”。智能体休眠一个月，只要期间没有新记忆产生，已有记忆完好如初，绝不因挂钟流逝而误删。
- **信息冲刷驱动**：衰减的动力来自**新信息的涌入量**。系统度量“自上次接触该记忆以来，智能体又经历了多少新信息序号”。
- **抗冲刷保留指数**：由记忆的**初始重要性、图谱关联总密度、被访问频次**综合决定。与其他记忆交织越紧密、被调用越频繁的记忆，对新信息冲刷的抵抗力越强（对数级巩固）。
- **自然淘汰**：保留指数低于阈值的孤立无用记忆被自动淘汰清理，保持心智系统始终清爽高效。

### 3. 主动联想与“回忆延伸”（图谱线索深挖）

普通向量检索只能被动喂养字面相似的文本，而无法发现深层逻辑关联：

- **双重关联编织**：新记忆入库时，系统基于**关键词重叠**与**语义向量相似度**自动建立带权重的关联边。
- **发散概念词（线索提供）**：检索命中某条记忆时，系统顺着图谱关联提取出一组**概念线索**一并交还给 AI。
- **主动深挖探索**：系统不强行塞入全部庞杂信息，而是把线索给 AI；AI 根据推理需要自主决定“这个线索值得深挖”，继而**主动调用检索工具发起下一步探索**。
- **正反馈机制**：被频繁召回和使用的记忆会增加权重和访问次数，在遗忘机制中享有更高存活率——用得越多，记得越牢。

### 4. 认知进化：从“记流水账”到“理论抽象与折叠”

智能体不仅能记录事实，更能自我提炼规律：

- **猜想与验证**：面对未知问题，AI 可提出猜想并打上标签（如 `[猜想]`），调用工具或执行运算去验证。
- **规律抽象与折叠**：当 AI 从多个具体案例中总结出通用规律时，提炼出高阶通用理论，并主动清理或降权那些冗余的具体琐碎案例，实现**“认知的精炼与升维”**。

### 5. 动态工具系统：从“记事”到“长出新技能”

大部分智能体的能力被局限在开发者写死的固定工具列表里：

- **运行时自主编写**：当 AI 发现某种数据转换、特定计算逻辑会被反复用到时，可以自主编写纯 JavaScript 代码将其注册为新工具。
- **自动化冒烟测试**：创建工具时附带测试用例，通过自动化隔离校验后才允许持久化入库。
- **语义自动召回**：后续遇到新问题时，系统根据用户需求语义自动提示相关的动态工具，AI 可随时调用。
- **QuickJS 隔离沙箱**：所有动态工具均在独立的 QuickJS 隔离沙箱中执行，无文件系统与网络访问权限，带超时限制，安全可控。

### 6. 工程底色：不可变原则与天然前缀缓存友好

- **上下文与记忆不可改写**：对话历史与记忆提交只追加不修改。这天然契合主流大模型商（OpenAI、DeepSeek、方舟等）的**前缀缓存（Prefix Caching）**机制，大幅减少重复计费与推理延迟。
- **零外部依赖嵌入式存储**：内置 WebAssembly 版 **PGlite + pgvector**，单进程本地运行，免去外部数据库搭建与部署成本。

## 场景实例：看看它在实际工作中有何不同

### 1. 顺藤摸瓜的主动联想（回忆延伸）

传统的向量检索只能单次被动喂养表面文本，而本库的图谱让 AI 具备像人一样“顺着线索自主深挖”的能力。

假设记忆库里此前分散记录了三条经验：

- **记忆 A**：`项目前端统一采用 Vue 3 + TailwindCSS，需适配黑暗模式`（关键词：前端规范）
- **记忆 B**：`所有弹窗与卡片均需适配 dark 模式，主题主色调为 emerald-500`（关键词：暗黑模式、主题色、弹窗）
- **记忆 C**：`所有弹窗内的表单统一使用 Vee-Validate + Zod 做校验，报错在输入框下方标红`（关键词：弹窗、表单校验、Zod）

> 传统检索面对“帮我写个前端登录组件”，通常只能根据提问字面搜出技术栈大纲（记忆 A），根本不会知道暗黑模式的具体主题色是什么，更联想不到深层的表单校验规范。

**而在本库中的实际运行过程：**

1. **初次唤醒**：用户提出需求 _"帮我写一个前端登录组件"_。系统通过初次检索命中了最相关的**记忆 A**。
2. **线索发散**：记忆 A 提到“需适配黑暗模式”。系统顺着关联图谱提取并返回了发散概念关键词：`暗黑模式`、`主题色`。
3. **深入查找记忆 B**：AI 拿到线索后，主动发起第二轮记忆检索 `暗黑模式 主题色`，精准调出**记忆 B**——由此获得了暗黑模式的落地细节（`dark:` 样式与 `emerald-500` 主色调）。
4. **二次发散**：在调出记忆 B 的同时，系统顺着图谱关联延伸出了下一层关键词：`弹窗`。
5. **深入查找记忆 C**：AI 再次主动检索 `弹窗`，调出深层的**记忆 C**（获得了 Vee-Validate + Zod 的规范）。
6. **最终输出**：AI 一步到位给出了既符合 Vue 3 + TailwindCSS、又原生适配暗黑与 emerald-500、还绑好了 Zod 校验规则的完整组件代码。

整个过程就像人脑联想一样，由 AI 沿着图谱线索**一环扣一环地主动探索**出来，无需人工把所有规范每次都重复复制进 prompt。

### 2. 跨会话记忆与抗遗忘：不靠时钟，靠“信息冲刷”

你在对话中告诉 AI：“以后写 TypeScript 绝对不要用 `any`，所有函数必须标明确切的返回类型”。

- **传统物理时钟遗忘的弊端**：如果按现实天数计算衰减，智能体闲置休眠一周，重新打开时记忆就会因为“超时”被误删；而如果在几分钟内灌入上万条数据，物理时钟才过去一分钟，系统反而来不及遗忘，导致上下文瞬间被挤爆。
- **在本库的“信息冲刷”机制下**：
  1. **休眠不衰减**：智能体闲置一个月没有任何交互（没有新记忆产生），这条偏好记忆的保留指数**完全不会衰减**，完好如初。
  2. **经历海量新信息的冲刷**：后来系统接入了处理财务报表的任务，短时间内涌入了 300 条全新的财务与税务数据。所有旧记忆都会经历这 300 条新信息的剧烈“冲刷”。
  3. **自然分流淘汰**：
     - 当时随口聊的一句琐碎闲聊（如“今天天气不错”）：由于**缺乏图谱关联（孤立节点）**，且**从未被再次访问过**，在 300 条新信息的冲刷下，保留指数迅速跌破阈值，被自然淘汰清除。
     - 代码风格偏好：它与系统内的工程知识形成关联网络，重要性评分高；即使经历了 300 条无关信息的冲刷，保留指数依然远高于淘汰线。
  4. **唤起与正反馈加固**：当用户随后突然说“帮我写个 CSV 解析函数”时，该偏好被重新命中，AI 依然严格输出 0 `any` 的规范代码；这次命中使它的访问频次递增，在未来能抵抗更大规模的信息冲刷。

### 3. 认知进化：从“记流水账”到“提炼规律”

智能体在日常调用某个第三方接口时，曾在不同日期零散地记下了几条错误记录：

- `"周一 00:02 调用外部结算 API 报错 502"`，标签：`[结算服务, 接口报错]`
- `"周三 00:04 结算 API 再次报错 502"`，标签：`[支付结算, 网关异常]`
- `"周五 00:01 结算 API 依然报 502"`，标签：`[第三方结算, 请求超时]`

在传统基于规则或 SQL 过滤的系统里，因为这几条记录的用词和标签各不相同，它们就是三条互不相干的数据孤岛。久而久之，成百上千条无意义的报错流水账会变成严重的检索噪音。

**认知升维与折叠过程：**

1. **语义聚集与联想碰撞**：虽然字面标签不同（“接口报错”与“网关异常”），但向量语义高度相近。在后续涉及结算问题时，本库的联想机制将这批记忆同时展现在 AI 的上下文中。
2. **模式识别（顿悟）**：几条记录并排摆在 AI 眼前时，AI 敏锐地比对了时间戳：_“周一 00:02、周三 00:04、周五 00:01……用词不同，但为什么全集中在零点刚过的那几分钟？”_
3. **提出猜想**：AI 推测：_“外部结算服务可能在每日 00:00~00:05 存在例行的定时重启维护”_，写入一条新记忆打上 `[猜想验证中]` 标签。
4. **确证与记忆折叠**：在夜间自动任务证实这一规律后，AI 意识到底层流水账已无保留价值：
   - 将之前具体的报错流水账**删除或降权淘汰**；
   - 抽象提炼出一条高阶通用规律：`[通用规律] 外部结算服务每日 00:00~00:05 进行例行维护，在此窗口期内的调用应自动执行 60 秒退避重试`。
5. 记忆库不仅没有随时间膨胀变慢，反而通过“联想碰撞 -> 提炼高阶规律”，完成了认知的精炼升维。

### 4. 动态工具：AI 自己给自己写“新技能”

假设你是一个跨国分布式团队的管理者，经常在会话里让 AI 计算跨时区的会议时间（比如东京、伦敦、纽约三地的工作时间交集）。

- **传统纯文本心算**：大模型每次都要在上下文里硬算时差、推导夏令时，一轮耗费上千 token，而且在跨日的心算中极易算错。
- **在本库中，AI 可以自我进化出新能力**：
  1. AI 发现这个计算需求频繁出现且逻辑确定，**主动用 JavaScript 编写了一个时区交集计算函数**，并附带了测试用例。
  2. 系统在独立的 QuickJS 隔离沙箱中自动运行冒烟测试。测试通过后，该函数被永久保存到智能体的动态工具库中。
  3. 以后只要再提出类似的时间计算，系统会自动匹配并把这个工具提供给 AI。AI 直接在沙箱内秒级运行，输出 100% 精确的计算结果。

智能体不再仅仅是“记事”，而是能够通过自写代码，不断扩充自己的能力边界。

## 快速上手

### 安装

```bash
pnpm add @lsby/ai-memory openai zod
```

> 要求 Node.js 20 及以上。

### 最小示例

`带记忆的智能体` 拥有开箱即用的长期记忆、记忆工具与会话能力：

```ts
import OpenAI from 'openai'
import { z } from 'zod'
import { 带记忆的智能体 } from '@lsby/ai-memory'

let 客户端 = new OpenAI({ apiKey: process.env['OPENAI_API_KEY'] ?? '' })

// 创建带长期记忆的智能体实例（持久化到本地目录）
let 智能体 = new 带记忆的智能体({
  系统提示词: '你是具备长期记忆的助手。',
  存储: { 模式: '文件', 路径: './data/memory' },
  向量模型: { 类型: '无' }, // 亦可配置本地或在线 embedding
})

let 结果 = await 智能体.对话({
  命令: '请记住：我们项目的生产环境数据库端口是 5433。',
  预期结果Schema: z.object({ 回答: z.string() }),
  预期结果描述: '对用户的回复',
  回调: async (): Promise<void> => {},
  openai客户端: 客户端,
  模型名称: 'gpt-4o-mini',
})

console.log(结果.结果?.回答)
```

### 存储模式

内置三种开箱即用的存储模式：

```ts
// 1. 内存模式：进程退出即清空，适合单元测试与临时无状态服务
let 内存实例 = new 带记忆的智能体({ 存储: { 模式: '内存' }, 向量模型: { 类型: '无' } })

// 2. 文件持久化模式：开箱即用，单进程目录文件持久化
let 文件实例 = new 带记忆的智能体({
  存储: { 模式: '文件', 路径: './data/memory' },
  向量模型: { 类型: '无' },
})

// 3. 外部句柄模式：传入已有 PGlite 句柄，支持多租户 Schema 隔离
let 外部实例 = new 带记忆的智能体({
  存储: { 模式: '外部', pglite: 自定义句柄, schema: 'u_user123' },
  向量模型: { 类型: '无' },
})
```
